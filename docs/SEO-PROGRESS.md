## Where things live (from Phase 0)

- Server is **Express**, not Fastify. Redirects: `LEGACY_REDIRECTS` in
  `apps/api/src/index.ts`. Each entry is one hop to a page that serves; the
  smoke test enforces that. Repoint entries when a better target exists (e.g.
  `/waiting-staff-london` to `/hire/waiting-staff` in Phase 3) rather than
  redirecting the old target.
- Rate: `apps/api/src/config/pricing.ts` is the source; pages carry a static
  fallback in a `data-vergo="rates.chargeRateDisplay"` element that
  `vergo-site-config.js` hydrates from `/api/v1/rates`. There is no `rates.html`
  or `pages/js/rates.js` any more.
- Header/footer: hand-copied into each page. `vergo-site-nav.js` turns the
  header links into the mobile menu. The blog pages are generated by
  `tools/blog/build.js`; their header/footer live in `tools/blog/template.js`.
  Only `login.html` (admin) still uses `vergo-public-shell.js`.
- Special events brief forms: `pages/js/halloween-team.js` drives every
  `form[data-se-brief]` and posts to `/api/v1/quotes` as an ENQUIRY.
- Checks: `npm test`, `npm run validate:pages`, `npm run validate:seo` (in
  `apps/api`). `validate:seo` now enforces titles, descriptions, og tags and
  sitemap membership.
- CSS/JS are served `Cache-Control: public, no-cache` (revalidate every time).
  They used to be cached 7 days without versioned URLs, which left returning
  phones with stale CSS against new HTML.
